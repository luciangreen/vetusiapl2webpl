# web_support — Helper Predicate Library (Stage 11)

`web_support.pl` is a self-contained SWI-Prolog module that provides all
the runtime helper predicates required by web programs generated by the
`vetusiapl2webpl` converter.

Generated programs may either:

- **Load this module** with `:- use_module(web_support).` — helpers are
  resolved at load time and the generated file stays lean.
- **Use inlined helpers** written by `emit_html_helpers/1` — every
  predicate is copied verbatim into the generated file, making it fully
  self-contained without any external dependency on this library.

---

## Module declaration

```prolog
:- use_module(web_support).
```

---

## Predicate reference

### 1. HTML fragment detection

| Predicate | Mode | Description |
|-----------|------|-------------|
| `looks_like_html/1` | `+Text:atom` | True when `Text` contains both `<` and `>` characters, indicating HTML markup. Plain strings like `'Enter name:'` fail. |

**Example**
```prolog
?- looks_like_html('<p>Hello</p>').   % true
?- looks_like_html('Enter name:').    % false
```

---

### 2. HTML escaping

| Predicate | Mode | Description |
|-----------|------|-------------|
| `html_escape/2` | `+In, -Out:atom` | Replace `&`, `<`, `>`, and `"` with their HTML entity equivalents (`&amp;`, `&lt;`, `&gt;`, `&quot;`). `In` may be an atom or a string; `Out` is always an atom. |

**Example**
```prolog
?- html_escape('<b>a & b</b>', Out).
Out = '&lt;b&gt;a &amp; b&lt;/b&gt;'.
```

---

### 3. Page structure

| Predicate | Mode | Description |
|-----------|------|-------------|
| `html_page_header/1` | `+Title` | Write `Content-type: text/html\n\n` followed by `<html><head><title>Title</title></head><body>`. |
| `html_page_footer/0` | — | Write `</body></html>`. |

**Example**
```prolog
html_page_header('My Page'),
% ... body content ...
html_page_footer.
```

---

### 4. Output helpers

| Predicate | Mode | Description |
|-----------|------|-------------|
| `html_writeln/1` | `+Text` | Writes `<p>Text</p>` for plain text; passes HTML atoms through with `~w~n`. |
| `html_write/1` | `+Text` | Writes `<span>Text</span>` for plain text; passes HTML atoms through with `~w`. |
| `html_br/0` | — | Writes `<br/>` followed by a newline. |
| `html_safe_writeln/1` | `+Text` | HTML-escapes `Text` then writes it wrapped in `<p>`. |
| `html_safe_write/1` | `+Text` | HTML-escapes `Text` then writes it inline (no wrapper). |

**Notes on string vs atom support**

- `html_writeln/1` and `html_write/1` accept any term printable with `~w`
  (atoms, strings, integers, floats).
- The HTML-fragment detection in `html_writeln/1` and `html_write/1` only
  fires for ground atoms; variables and strings are always wrapped.
- `html_safe_writeln/1` and `html_safe_write/1` first call `html_escape/2`
  (which handles both atoms and strings) and then write the escaped value.

**Example**
```prolog
html_writeln('Welcome!'),           % <p>Welcome!</p>
html_writeln('<h1>Dashboard</h1>'), % <h1>Dashboard</h1>   (pass-through)
html_br,                            % <br/>
html_safe_writeln('<script>xss</script>'),  % <p>&lt;script&gt;...
```

### 5. State (de)serialisation

| Predicate | Mode | Description |
|-----------|------|-------------|
| `state_serialise/2` | `+Term, -Atom:atom` | Convert any ground Prolog term to a canonical atom via `term_to_atom/2`. The atom is safe for use as an HTML hidden-field value. |
| `state_deserialise/2` | `+Atom:atom, -Term` | Parse a previously serialised atom back to its original term. Falls back to the identity (`Term = Atom`) when the atom is not valid Prolog syntax, preserving arbitrary user-typed text. |

**Round-trip guarantee**

For every ground term `T`:
```prolog
state_serialise(T, A), state_deserialise(A, T2)  ⇒  T2 == T
```

This holds for atoms, integers, floats, SWI strings, lists, and compound
terms.

**Example**
```prolog
?- state_serialise([1,2,3], A).
A = '[1,2,3]'.

?- state_deserialise('[1,2,3]', T).
T = [1, 2, 3].

?- state_deserialise('Hello World', T).
T = 'Hello World'.   % fallback — not a Prolog term, returned as-is
```

### 6. Request data extraction

| Predicate | Mode | Description |
|-----------|------|-------------|
| `ws_request_param/3` | `+Request, +Name:atom, -Value` | Extract a single named parameter from the HTTP request. Equivalent to `http_parameters(Request, ['Name'(Value, [atom])])`. |
| `ws_request_params/2` | `+Request, +Specs:list` | Extract multiple parameters in one call. `Specs` is a list of `Name=Variable` pairs. |

**Example**
```prolog
% Single parameter
ws_request_param(Request, 'Username', Username),

% Multiple parameters
ws_request_params(Request, ['Username'=Username, 'Password'=Password]),
```

### 7. Raw-HTML form output

These predicates write form HTML directly to `current_output` using
`format/1-2`.  They are useful in result-page handlers and in programs
that do not use SWI-Prolog's `reply_html_page/2`.

| Predicate | Mode | Description |
|-----------|------|-------------|
| `ws_form_open/2` | `+Action:atom, +Method:atom` | Write `<form action="Action" method="Method">`. |
| `ws_form_close/0` | — | Write `</form>`. |
| `ws_text_input/1` | `+Name:atom` | Write `<input type="text" name="Name" autofocus/>`. |
| `ws_password_input/1` | `+Name:atom` | Write `<input type="password" name="Name" autofocus/>`. |
| `ws_textarea_input/1` | `+Name:atom` | Write a `<textarea>` element (5 rows × 40 cols) with autofocus. |
| `ws_hidden_input/2` | `+Name:atom, +Value` | Write `<input type="hidden" …/>` with the value HTML-escaped. |
| `ws_submit/1` | `+Label:atom` | Write `<input type="submit" value="Label"/>`. |

**Example**
```prolog
html_page_header('Enter Details'),
ws_form_open('/step_1', post),
ws_hidden_input('Username', Username),
html_writeln('Enter your age:'),
ws_text_input('Age'),
ws_submit('Next'),
ws_form_close,
html_page_footer.
```

## Compatibility with inlined helpers

The `emit_html_helpers/1` predicate in `html_output.pl` generates identical
definitions for the overlapping helpers (`looks_like_html`, `html_escape`,
`html_writeln`, `html_write`, `html_safe_writeln`, `html_safe_write`,
`html_page_header`, `html_page_footer`, `state_serialise`,
`state_deserialise`) so that generated programs using inlined helpers behave
identically to those loading `web_support.pl`.

To load `web_support.pl` from a generated file instead of inlining, call
`emit_web_support_loader/1` (from `html_output`) in place of
`emit_html_helpers/1`.
